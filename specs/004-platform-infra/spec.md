# Feature Specification: Platform Infrastructure

**Feature branch**: `feat/pr4-platform-infra` · **Status**: Draft · **Owner**: PR4

## Summary

Package and run the Payments platform (`payments-platform`, Spring Boot 3.5 / Java 21)
consistently on a laptop (Docker Compose), in Kubernetes (kustomize base + overlays) and on
managed hosts (Railway primary, Render and Cloud Run alternatives), with a CI gate that can
run identically on GitHub Actions and locally. Infra files only — no `src/`, `pom.xml` or
application config changes.

## User scenarios

1. **Developer bootstraps locally** — `cp .env.example .env && docker compose up --build`
   starts app + PostgreSQL 16 + Redis 7 + RabbitMQ 3.13; the app starts only after every
   dependency is healthy, and reports healthy via `/actuator/health/readiness`.
2. **Reviewer runs the gate** — `scripts/ci-local.sh` runs the same checks as
   `.github/workflows/ci.yml` (Maven verify, compose config, image build, kustomize render +
   kubeconform) and exits non-zero on any failure.
3. **Operator deploys to Kubernetes** — `kustomize build deploy/k8s/overlays/<env>` renders
   valid manifests (Kubernetes ≥ 1.30, strict schema) with probes, resources, HPA, PDB,
   TLS ingress, non-root read-only pods and a one-shot Flyway migration Job.
4. **Operator deploys to a PaaS** — `railway.json`, `render.yaml` and
   `deploy/cloudrun/service.yaml` describe the service with placeholder secrets only.

## Functional requirements

- **FR-001** Multi-stage `Dockerfile`: Maven + JDK 21 build stage with BuildKit cache for
  `~/.m2`; JRE 21 runtime; Spring Boot layered extraction; artifact-agnostic (`target/*.jar`);
  non-root numeric UID; container-aware JVM flags via `JAVA_OPTS`; honours `PORT`.
- **FR-002** `docker-compose.yml` with healthchecks for every service, named volumes,
  `depends_on: condition: service_healthy`, ports bound to `127.0.0.1`, values from `.env`.
- **FR-003** `.env.example` lists every variable with clearly-marked dev-only dummies; JWT
  keys empty and generated by `scripts/generate-jwt-keys.sh` (openssl, RSA 2048, PKCS#8).
- **FR-004** Kustomize base + `staging`/`production` overlays: Namespace, Deployment
  (startup/readiness/liveness probes, requests/limits, non-root, read-only rootfs + `/tmp`
  emptyDir, preStop + grace period, `maxUnavailable: 0`), Service, ConfigMap, Secret
  references only (`secret.example.yaml` excluded from kustomization), HPA (CPU + memory),
  PDB, Ingress (ingress-nginx, cert-manager TLS), NetworkPolicy, Flyway migration Job.
- **FR-005** `.github/workflows/ci.yml` on PR + push to `main`: `mvn -B clean verify`,
  docker build (no push), hadolint, kustomize render + kubeconform.
- **FR-006** `scripts/ci-local.sh` reproduces the CI gate locally.
- **FR-007** Hosting descriptors: `railway.json`, `render.yaml`, `deploy/cloudrun/service.yaml`.
  No deploy and no cost-generating action is performed by this PR.

## Runtime contract consumed from PR1 (application side)

| Variable | Meaning |
|---|---|
| `SPRING_PROFILES_ACTIVE` | `local` (compose) / `prod` (k8s, PaaS) |
| `DB_URL`, `DB_USER`, `DB_PASSWORD` | JDBC PostgreSQL connection |
| `REDIS_HOST`, `REDIS_PORT`, `REDIS_PASSWORD` | Redis |
| `RABBITMQ_HOST`, `RABBITMQ_PORT`, `RABBITMQ_USER`, `RABBITMQ_PASSWORD` | RabbitMQ |
| `JWT_PRIVATE_KEY`, `JWT_PUBLIC_KEY`, `JWT_ISSUER`, `JWT_AUDIENCE` | RS256 signing (PEM) |
| `SPRING_FLYWAY_ENABLED` | `true` = migrate on startup (compose/PaaS), `false` in k8s Deployment |
| `APP_MIGRATION_ONLY` (`app.migration-only`) | `true` = run Flyway then exit (k8s Job) — **to be wired by PR1/PR8** |

Probes: `/actuator/health/liveness`, `/actuator/health/readiness`; metrics `/actuator/prometheus`.

## Non-goals

Observability stack (PR7), application code, real deployments, managed databases provisioning.

## Success criteria

- `docker compose config` valid; `kubeconform -strict` (k8s 1.30) passes for both overlays;
  hadolint clean; `bash -n` on scripts; image builds from current `main`.
- After PR1 merges: image builds and `docker compose up` reaches healthy readiness.
